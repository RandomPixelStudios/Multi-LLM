DocumentationDokumentation

Everything you need to install Multi LLM, connect your tools, and run it for a whole team – collected from the app itself. You never need to compile anything: every path below uses ready-made packages or Docker.

Alles, was du brauchst, um Multi LLM zu installieren, deine Tools zu verbinden und es für ein ganzes Team zu betreiben – direkt aus der App. Du musst nichts kompilieren: Alle Wege unten nutzen fertige Pakete oder Docker.

InstallationInstallation

Pick the install that matches how you work. Solo on your machine → desktop app. Team or server → Docker.

Windows (desktop)

  1. Download the .exe installer and run it.
  2. Start Multi LLM from the Start menu. It lives in the system tray while running.
  3. Optional: enable Start with Windows in Settings → App so the proxy is up when you sign in.

Linux (desktop)

  1. Download the .deb package and install it:
    sudo apt install ./multi-llm_1.0.5_amd64.deb
  2. Launch Multi LLM from your application menu. A tray icon shows the running state.

Docker (teams & servers)

Needs only Docker Engine + Compose plugin – no Node, no Rust, no compilers. Full walkthrough in Quick start below.

What you need in all cases

  • Network access to the providers you use (cloud APIs need internet; local providers like Ollama need to run on your machine).
  • At least one provider API key – e.g. OpenAI, Anthropic, or a local engine that needs none.
  • A free local port – desktop default is 5000 (changeable); Docker always uses container port 5000, so host port 5000 must be free.

Wähle die Installation passend zu deiner Arbeitsweise. Solo am Rechner → Desktop-App. Team oder Server → Docker.

  3. Optional: aktiviere Start mit Windows unter Einstellungen → App, damit der Proxy bei der Anmeldung läuft.

Docker (Teams & Server)

Braucht nur Docker Engine + Compose-Plugin – kein Node, kein Rust, keine Compiler. Komplette Anleitung unten unter Schnellstart.

Was du in allen Fällen brauchst

  • Netzwerkzugriff auf deine Provider (Cloud-APIs brauchen Internet; lokale Provider wie Ollama müssen auf deinem Rechner laufen).

  • Einen freien lokalen Port – Desktop-Standard ist 5000 (änderbar); Docker nutzt immer Container-Port 5000, also muss Host-Port 5000 frei sein.

Verify your setupSetup prüfen

Two commands prove the proxy works. Replace KEY with your API key.

1. List models – you should see multillm plus your enabled models (or only multillm, depending on the All models switch):

curl http://localhost:5000/v1/models \ -H "Authorization: Bearer KEY"

2. Chat completion – routes through the proxy with failover:

curl http://localhost:5000/v1/chat/completions \ -H "Authorization: Bearer KEY" \ -H "Content-Type: application/json" \ -d '{"model":"multillm","messages":[{"role":"user","content":"Say OK"}]}'

3. Streaming – add "stream": true and you get standard SSE chunks (data: {...}) ending with data: [DONE].

If the model name is wrong or disabled, the API answers with a plain-text hint like: “The model 'x' does not exist or is not enabled. Use GET /v1/models to list available models.” – then check the Models tab.

Concepts: how a request flowsKonzepte: Weg eines Requests

  1. Client → proxy. Your tool sends an OpenAI-style request to /v1/… with your key.
  2. Auth + resolve. The key is checked, the model name resolves to multillm, a bundle, or one concrete model.
  3. Router picks. The strategy (e.g. weighted ×4 for stars) chooses a member; sticky sessions pin conversations.
  4. Upstream call. The prompt (optionally compressed, optionally cached) goes to the provider.
  5. Failover if needed. On 429/5xx or network failure, the next candidate is tried automatically.
  6. Stream back + log. Tokens stream to your client byte-identical; counts land in Usage.
  1. Client → Proxy. Dein Tool sendet einen OpenAI-artigen Request an /v1/… mit deinem Key.
  2. Auth + Auflösen. Der Key wird geprüft, der Modellname löst zu multillm, Bundle oder konkretem Modell auf.
  3. Router wählt. Die Strategie (z. B. weighted ×4 für Sterne) wählt ein Member; Sticky Sessions pinnen Unterhaltungen.
  4. Upstream-Call. Der Prompt (optional komprimiert, optional gecached) geht an den Provider.
  5. Failover bei Bedarf. Bei 429/5xx oder Netzfehler wird automatisch der nächste Kandidat versucht.
  6. Stream zurück + Log. Tokens streamen byte-identisch zum Client; Zähler landen in Usage.

Concepts: streaming vs. non-streamingKonzepte: Streaming vs. non-streaming

  • Streaming ("stream": true) – tokens arrive as SSE chunks while generating. Use for chats and agents: faster perceived speed, same cost.
  • Non-streaming – one full JSON answer. Use for scripts, evals, and cached repeats (only non-streaming temperature: 0 calls are cacheable).
  • Both paths share routing, failover, compression, and Usage logging.
  • Streaming ("stream": true) – Tokens kommen als SSE-Chunks schon während der Generierung. Für Chats und Agents: gefühlt schneller, gleiche Kosten.
  • Non-streaming – eine komplette JSON-Antwort. Für Skripte, Evals und gecachte Wiederholungen (nur non-streaming temperature: 0-Calls sind cachbar).
  • Beide Wege teilen Routing, Failover, Kompression und Usage-Logging.

GlossaryGlossar

  • Provider – a connected API source (OpenAI, Anthropic, Ollama, …).
  • Model – one enabled model on a provider.
  • Virtual model – a named bundle of models under one API name.
  • multillm – the built-in bundle of everything enabled.
  • Star – favorite marker; starred models win 4× more often under weighted routing.
  • Alias – auto-generated id (e.g. o-gpt-4o) when one model id lives on two providers.
  • Routing – how a member is picked per request (6 strategies).
  • Failover – automatic retry on the next candidate after upstream failure.
  • Circuit breaker – pauses chronically failing providers.
  • Health – the green/yellow/red status dot per provider.
  • Compression – prompt shrinking before upstream (strength 1–10).
  • Cache – repeats identical temperature: 0 answers without asking upstream.
  • Usage – token/request statistics per model.
  • Expose LAN – serve API + UI to other devices on your network.
  • Provider – eine angebundene API-Quelle (OpenAI, Anthropic, Ollama, …).
  • Modell – ein aktiviertes Modell eines Providers.
  • Virtuelles Modell – benanntes Bundle von Modellen unter einem API-Namen.
  • multillm – eingebautes Bundle aus allem Aktivierten.
  • Stern – Favoriten-Markierung; gestarrte Modelle gewinnen 4× häufiger unter Weighted-Routing.

Configuration: reliabilityKonfiguration: Zuverlässigkeit

  • Failover. If an upstream answers 429/5xx or the network fails, the request automatically moves to the next candidate. Rate-limited candidates are parked briefly (observing retry hints, capped at 60 s). Successful streams pass through byte-identical.
  • Circuit breaker (optional, off by default). After 3 failures a provider pauses for 60 s, then exactly one probe request is let through; success resets it, failure extends the pause (up to 10 min).
  • Response cache (optional, off by default). Caches identical non-streaming requests with temperature: 0 and no tools for 300 s (50 entries). Bypass per request with header x-multillm-cache: bypass or Cache-Control: no-store.
  • Budgets (optional). Cap attempts per request or abort hanging streams after a first-token timeout so a stuck upstream never blocks you.
  • Failover. Antwortet ein Upstream mit 429/5xx oder scheitert das Netz, wandert der Request automatisch zum nächsten Kandidaten. Limitierte Kandidaten werden kurz geparkt (Retry-Hinweise beachtet, max. 60 s). Erfolgreiche Streams laufen byte-identisch durch.
  • Circuit Breaker (optional, standardmäßig aus). Nach 3 Fehlern pausiert ein Provider 60 s, dann wird genau ein Probe-Request durchgelassen; Erfolg setzt zurück, Fehler verlängert die Pause (bis 10 Min.).
  • Response-Cache (optional, standardmäßig aus). Cached identische Non-Streaming-Requests mit temperature: 0 ohne Tools für 300 s (50 Einträge). Pro Request umgehbar per Header x-multillm-cache: bypass oder Cache-Control: no-store.
  • Budgets (optional). Begrenze Versuche pro Request oder brich hängende Streams nach First-Token-Timeout ab, damit ein klemmender Upstream nie blockiert.

Docker: security notesDocker: Sicherheitshinweise

  • Login mandatory. The web UI and dashboard expose nothing without a session – strangers on your LAN see only the login screen.
  • Per-user isolation. Keys and sessions map to exactly one profile; users cannot see or spend each other's providers.
  • Hashed secrets. Inbound keys are compared as hashes, and provider secrets live in per-user secret files with restrictive permissions.
  • Non-root container. The app runs as an unprivileged user with a private data directory.
  • No autostart. After a host reboot nothing runs until you start it – no surprise exposure.
  • Still HTTP. LAN traffic is unencrypted HTTP. Fine at home; never expose port 5000 directly to the internet – use a VPN or reverse proxy with TLS if you must go remote.
  • Login-Pflicht. Web-UI und Dashboard zeigen ohne Session nichts – Fremde im LAN sehen nur den Login.
  • Isolation pro Nutzer. Keys und Sessions gehören zu genau einem Profil; niemand sieht oder verbraucht fremde Provider.
  • Gehashte Secrets. Inbound-Keys werden als Hashes verglichen, Provider-Secrets liegen in Nutzer-Secret-Dateien mit restriktiven Rechten.
  • Non-Root-Container. Die App läuft als unprivilegierter Nutzer mit privatem Datenverzeichnis.
  • Kein Autostart. Nach Host-Reboot läuft nichts bis zum manuellen Start – keine Überraschungen.
  • Trotzdem HTTP. LAN-Traffic ist unverschlüsseltes HTTP. Zuhause ok; Port 5000 nie direkt ins Internet – remote nur per VPN oder Reverse-Proxy mit TLS.

Docker: limitsDocker: Grenzen

  • No native window, tray icon, or launch-at-login – the browser UI replaces them.
  • Exactly one fixed port (5000). One container = one team server; need two? Run a second stack with its own volume and project name.
  • Updates mean rebuilding the image (or transferring it with docker save/load).
  • Provider traffic still needs internet from the host unless you only use local engines reachable from the container (note: localhost inside the container is not your host – point local providers at the host's LAN IP).
  • Kein natives Fenster, Tray-Icon oder Autostart – die Browser-UI ersetzt sie.
  • Genau ein fester Port (5000). Ein Container = ein Team-Server; zwei nötig? Zweiten Stack mit eigenem Volume und Projektnamen fahren.
  • Updates = Image neu bauen (oder per docker save/load transferieren).
  • Provider-Traffic braucht weiter Internet vom Host, außer es laufen nur lokale Engines, die der Container erreicht (Achtung: localhost im Container ist nicht dein Host – lokale Provider auf die LAN-IP des Hosts zeigen).

FAQ

Are my provider keys safe?

Yes. They live in a restricted local store on your machine (desktop) or in your isolated Docker profile, and inbound keys are compared as hashes. Keys only ever travel to the provider itself.

Does Multi LLM cost money?

The proxy is free – you pay your providers' token prices. Cut them with compression, cache, cheap bundles, and the Usage review.

Does it work offline?

With local engines (Ollama, LM Studio, …) yes, fully. Cloud providers need internet. This website is static and needs no backend at all.

Which systems are supported?

Windows and Linux via the desktop app, anything Docker runs on via the team image.

Desktop or Docker?

Solo on your machine → desktop. Shared server or team → Docker (see the comparison table).

A model is missing in my client.

Enable it in the Models tab, check the All models switch (or just use multillm), and re-list via GET /v1/models.

Is streaming supported?

Yes – standard SSE chunks ending with data: [DONE], passed through byte-identical on success.

One key for the whole team?

No – and that is on purpose. Docker gives every user a personal stable key; desktop has one rerollable key. Never share keys between people.

Sind meine Provider-Keys sicher?

Ja. Sie liegen im geschützten lokalen Speicher deines Rechners (Desktop) bzw. deines isolierten Docker-Profils; Inbound-Keys werden als Hashes verglichen. Keys wandern nur zum Provider selbst.

Kostet Multi LLM Geld?

Der Proxy ist gratis – du zahlst die Token-Preise deiner Provider. Senken per Kompression, Cache, günstigen Bundles und Usage-Review.

Läuft es offline?

Mit lokalen Engines (Ollama, LM Studio, …) ja, komplett. Cloud-Provider brauchen Internet. Diese Website ist statisch und braucht gar kein Backend.

Welche Systeme werden unterstützt?

Windows und Linux per Desktop-App, alles mit Docker per Team-Image.

Desktop oder Docker?

Solo am Rechner → Desktop. Geteilter Server oder Team → Docker (siehe Vergleichstabelle).

Modell fehlt im Client.

Im Models-Tab aktivieren, All models-Schalter prüfen (oder einfach multillm nutzen) und per GET /v1/models neu listen.

Wird Streaming unterstützt?

Ja – Standard-SSE-Chunks bis data: [DONE], bei Erfolg byte-identisch durchgereicht.

Ein Key fürs ganze Team?

Nein – Absicht. Docker gibt jedem Nutzer einen persönlichen stabilen Key; Desktop hat einen neu würfelbaren Key. Keys nie zwischen Personen teilen.

Where is my data stored?

Desktop: in your local app profile on the machine. Docker: per user under /data/users/<name>/ inside the multillm-data volume. Export config JSON any time as a portable copy.

How do I start over?

Delete providers (double-click the trash icon) and virtual models to return to an empty state – or reinstall the desktop app / recreate the Docker volume for a full reset (data is lost, so export first).

Can one provider key serve everything?

Yes – one provider can expose many models, and multillm mixes models across providers. Most solo setups need exactly one cloud key plus local engines.

Does the app phone home?

Only the update check, and only if enabled (Settings → App) or when you press Check now. There is no telemetry and no usage reporting.

What if my provider raises prices?

Watch the Usage ranking, move bulk work to a cheap bundle, turn on compression, and reroute – no client changes needed.

Can I run two instances at once?

The desktop app runs once (second launch focuses the running window). Need two setups? Run a second Docker stack with its own volume.

Wo liegen meine Daten?

Desktop: im lokalen App-Profil auf dem Rechner. Docker: pro Nutzer unter /data/users/<name>/ im Volume multillm-data. Config-JSON jederzeit als portable Kopie exportieren.

Wie fange ich neu an?

Provider löschen (Doppelklick aufs Müll-Icon) und virtuelle Modelle entfernen für leeren Stand – oder Desktop-App neu installieren / Docker-Volume neu anlegen für Full-Reset (Daten weg, also erst exportieren).

Reicht ein Provider-Key für alles?

Ja – ein Provider kann viele Modelle liefern und multillm mischt über Provider hinweg. Die meisten Solo-Setups brauchen genau einen Cloud-Key plus lokale Engines.

Telefoniert die App nach Hause?

Nur der Update-Check, und nur wenn aktiviert (Settings → App) oder per Check-now-Button. Keine Telemetrie, kein Usage-Reporting.

Was bei Provider-Preiserhöhung?

Usage-Ranking beobachten, Bulk-Arbeit ans günstige Bundle, Kompression an, umrouten – keine Client-Änderungen nötig.

Zwei Instanzen gleichzeitig?

Die Desktop-App läuft einmal (zweiter Start fokussiert das laufende Fenster). Zwei Setups nötig? Zweiten Docker-Stack mit eigenem Volume fahren.

Can I use it commercially?

The proxy routes to providers under your own provider contracts – check their business terms and the MultiLLM project license with the project owner. Nothing in the app restricts commercial prompts.

How do I update virtual bundles?

Virtual Models tab → open the bundle (or delete + recreate it), change members or strategy, Save. Clients using the bundle name pick it up on the next request – no client changes.

Why is my model slow?

Check its tok/s card value and run Test for latency. Route latency-sensitive work to a fastest bundle, enable compression, and prefer streaming so first tokens arrive early.

How do I pause a provider temporarily?

Disable its models (provider editor) or delete the provider – re-add it any time via presets. Usage history is kept.

How do I report bugs?

Join the Discord community server (button, top right) with: what you did, what you expected, the exact error text, and your setup (desktop OS or Docker). Export config JSON (without keys) if it helps reproduce.

Are there rate limits?

The proxy itself imposes none – your providers' quotas apply. Their 429s trigger automatic failover to the next member, so bursts survive.

Darf ich es kommerziell nutzen?

Der Proxy routet zu Providern unter deinen eigenen Provider-Verträgen – deren Business-Bedingungen plus MultiLLM-Projektlizenz beim Owner prüfen. Nichts in der App beschränkt kommerzielle Prompts.

Wie update ich virtuelle Bundles?

Virtual-Models-Tab → Bundle öffnen (oder löschen + neu anlegen), Member oder Strategie ändern, Save. Clients mit dem Bundle-Namen greifen ab dem nächsten Request zu – keine Client-Änderung.

Warum ist mein Modell langsam?

tok/s-Kartenwert prüfen und Test für Latenz laufen lassen. Latenzsensible Arbeit ans fastest-Bundle routen, Kompression an, Streaming bevorzugen, damit erste Tokens früh kommen.

Wie pausiere ich einen Provider temporär?

Seine Modelle deaktivieren (Provider-Editor) oder Provider löschen – jederzeit per Preset neu anlegen. Usage-Historie bleibt.

Discord-Community-Server joinen (Button oben rechts) mit: Was getan, was erwartet, exakter Fehlertext, Setup (Desktop-OS oder Docker). Config-JSON exportieren (ohne Keys), falls es Repro hilft.

Gibt es Rate-Limits?

Der Proxy selbst hat keine – es gelten die Quoten deiner Provider. Deren 429er triggern automatisches Failover zum nächsten Member, Bursts überleben.

multillm with weighted routing. Use it for a week, check Usage, then star your two favorites.

Why do two providers list the same model?

The same id enabled twice gets an automatic alias (e.g. o-gpt-4o) so you can target each copy exactly.

What does the yellow dot mean?

Unknown or stale probe – not an error. Run Test to refresh it; red means failing or breaker open.

Can I work offline on a plane?

Yes, with local engines connected. Cloud providers stay unreachable; the app and this page need no internet otherwise.

How do I delete my data?

Delete providers and bundles (double-click the trash icon). Docker: delete the user – or the whole volume (export first).

Do I need a GPU for Docker?

No. The container only forwards requests; providers do the compute. Only self-hosted local engines benefit from a GPU.

Mit welchem Modell starten?

multillm mit Weighted-Routing. Eine Woche nutzen, Usage prüfen, dann zwei Favoriten sternen.

Dieselbe ID zweimal aktiviert bekommt automatisch einen Alias (z. B. o-gpt-4o) – jede Kopie exakt ansteuerbar.

Was bedeutet der gelbe Punkt?

Unbekannte oder veraltete Probe – kein Fehler. Test laufen lassen zum Auffrischen; rot heißt Fehler oder offener Breaker.

Offline im Flugzeug arbeiten?

Ja, mit verbundenen lokalen Engines. Cloud-Provider bleiben unerreichbar; App und Seite brauchen sonst kein Internet.

Wie lösche ich meine Daten?

Provider und Bundles löschen (Doppelklick aufs Müll-Icon). Docker: Nutzer löschen – oder ganzes Volume (erst exportieren).

Brauche ich eine GPU für Docker?

Nein. Der Container leitet nur weiter; rechnen tun die Provider. Nur selbstgehostete lokale Engines profitieren von GPU.
