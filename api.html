API reference

The OpenAI-compatible surface, the error format, and copy-paste recipes for the common calls.

Authentication

Every request needs your local key. It authenticates you to your own proxy; it is not a provider credential.

Authorization: Bearer YOUR_LOCAL_KEY

Without a valid key the response is 401 with invalid_api_key. Extra keys may be limited to specific models or to a requests-per-minute ceiling; exceeding the ceiling gives 429.

Your provider keys are never involved

Your tool authenticates with the local key. Multi LLM uses your provider keys on the far side, and neither key is visible to the other.

Inference endpoints

Standard OpenAI paths under /v1. Anything outside this list is refused rather than relayed blindly.

MethodPathBody
POST/v1/chat/completionsmodel, messages, optional stream, temperature, max_tokens, tools
POST/v1/completionsmodel, prompt
POST/v1/responsesmodel, input
POST/v1/embeddingsmodel, input
POST/v1/moderationsinput
GET/v1/models—
POST/v1/images/*relayed to the provider
POST/v1/audio/*relayed to the provider

The request is translated to whatever the resolved provider speaks. A body that OpenAI accepts therefore works against an Anthropic or Gemini model without changes on your side.

Base URL

http://localhost:5000/v1

Models

GET /v1/models returns the ids your tools may request:

{ "object": "list", "data": [ { "id": "multillm", "object": "model", "owned_by": "local" }, { "id": "gpt-4o", "object": "model", "owned_by": "openai" } ] }

The list contains enabled models plus the virtual models you created. Models that exist but are switched off appear only if All models is on in the API panel.

Most tools do not call this at all — they use whatever you type into their model field. It is still useful for scripts and for troubleshooting.

Error format

Errors follow the OpenAI shape, so SDKs that expect it work unchanged:

{ "error": { "code": "invalid_api_key", "message": "Missing or invalid API key.", "type": "invalid_request_error" } }
HTTPcodeMeaning
400invalid_requestMalformed body, or a model the proxy cannot resolve
401invalid_api_keyMissing or wrong local key
404model_not_foundThe model does not exist or is not enabled
404not_foundThe path is not one of the relayed endpoints
429rate_limitExtra key rate limit reached
502upstream_errorThe provider failed; the message carries its reason
503no_providerNo healthy model in the bundle, or the breaker is open everywhere

An upstream 502 contains the provider's own error text, so you can tell a rate limit there from a quota problem.

Headers and limits

Request size
64 MB on /v1, 8 MB on management endpoints.
Stream timeout
20 seconds to first byte, then the connection stays open for the stream.
Failed logins
10 per minute per IP, then a 60-second block.
Key comparison
Constant time, so a wrong key cannot be found by measuring.

Request forwarding

Your headers pass through to the provider unless they are proxy-specific. The Authorization header is the exception: it is replaced with the provider's own credential, and yours never leaves the machine.

Cookbook: a chat request

curl http://localhost:5000/v1/chat/completions \ -H "Authorization: Bearer YOUR_LOCAL_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "multillm", "messages": [ { "role": "system", "content": "Answer in one sentence." }, { "role": "user", "content": "What is a circuit breaker?" } ], "temperature": 0.2 }'

Lower temperature for factual questions, higher for open-ended ones. It is forwarded to the provider unchanged.

Cookbook: streaming

curl -N http://localhost:5000/v1/chat/completions \ -H "Authorization: Bearer YOUR_LOCAL_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "multillm", "messages": [{"role": "user", "content": "Write a haiku about proxies."}], "stream": true }'

-N disables curl's own buffering. Without it the output still arrives, but in one piece at the end.

Cookbook: list models

curl -s http://localhost:5000/v1/models \ -H "Authorization: Bearer YOUR_LOCAL_KEY" \ | jq -r '.data[].id'

Paste the output straight into a tool's model field. If a name is missing from this list, that tool cannot use it.

Cookbook: embeddings

curl http://localhost:5000/v1/embeddings \ -H "Authorization: Bearer YOUR_LOCAL_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "text-embedding-3-small", "input": "Multi LLM routes every provider behind one endpoint." }'

Embeddings bypass routing — the model is used exactly as named. They also bypass failover, because a partial vector is worse than none.

Cookbook: the Responses API

curl http://localhost:5000/v1/responses \ -H "Authorization: Bearer YOUR_LOCAL_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "multillm", "input": "Name three benefits of a local proxy." }'

For tools written against OpenAI's newer Responses interface. The request is translated to whichever provider the bundle picks.

Cookbook: choosing a model explicitly

Replace multillm in any of the above with:

  • gpt-4o — exactly that provider's model, no routing
  • cheap — your own bundle, strategy decides
  • private — local models only

Exact ids still fail over, because the circuit breaker applies to the provider regardless. Bundles fail over and choose.

Cookbook: Node

import OpenAI from "openai"; const client = new OpenAI({ baseURL: "http://localhost:5000/v1", apiKey: "YOUR_LOCAL_KEY", }); const stream = await client.chat.completions.create({ model: "multillm", messages: [{ role: "user", content: "Explain failover in two sentences." }], stream: true, }); for await (const chunk of stream) { process.stdout.write(chunk.choices[0]?.delta?.content ?? ""); }

Cookbook: Python

from openai import OpenAI client = OpenAI( base_url="http://localhost:5000/v1", api_key="YOUR_LOCAL_KEY", ) stream = client.chat.completions.create( model="multillm", messages=[{"role": "user", "content": "Explain failover in two sentences."}], stream=True, ) for chunk in stream: print(chunk.choices[0].delta.content or "", end="", flush=True)

There is nothing Multi-LLM-specific in either SDK. The three values are the whole integration.

Cookbook: jq

curl -s http://localhost:5000/v1/chat/completions \ -H "Authorization: Bearer YOUR_LOCAL_KEY" \ -H "Content-Type: application/json" \ -d '{"model":"multillm","messages":[{"role":"user","content":"ping"}]}' \ | jq -r '.choices[0].message.content'

For shell scripts and health checks. Add | jq -r '.usage.total_tokens' to see the cost of one call.
