Field names differ per tool

Almost every tool has the same three values, but the names are not the same everywhere. This is the single most common reason a tool keeps talking to the real OpenAI after you thought you pointed it at Multi LLM: the tool ignores an unrecognised field and falls back to its default endpoint.

The /v1 suffix

Most tools want the base URL with /v1 at the end. Claude Code is the exception: it wants the bare address without a path, because it appends the Anthropic path itself. Getting this backwards is the most common single mistake.

Step by step

Every entry gives the exact path to the setting, a ready-to-paste configuration, and what that particular tool does with your input. The placeholder YOUR_LOCAL_KEY is the key from API → API Keys.

Editor

Cline

Cline

Where: The sidebar gear icon › API Provider › OpenAI Compatible

{ "provider": "openai", "openAiBaseUrl": "http://localhost:5000/v1", "openAiApiKey": "YOUR_LOCAL_KEY", "openAiModelId": "multillm" }

Cline uses openAiBaseUrl and openAiApiKey. Both must be set; an empty base URL falls back to the official OpenAI endpoint.

Continue

Continue

Where: Config gear › Models › Add a model › OpenAI

{ "models": [ { "title": "multillm", "provider": "openai", "model": "multillm", "apiBase": "http://localhost:5000/v1", "apiKey": "YOUR_LOCAL_KEY" } ] }

Continue names the field apiBase, not baseUrl. A baseUrl here is silently ignored and requests go to api.openai.com.

Cursor

Cursor

Where: Settings › Models › API Keys › Add custom model

{ "name": "multillm", "apiKey": "YOUR_LOCAL_KEY", "baseUrl": "http://localhost:5000/v1", "provider": "openai" }

Pick OpenAI as the provider, then switch every other model off in the list so queries do not go to a provider that needs a real key.

Kilo Code

Kilo Code

Where: Kilo icon › Settings › API Provider › OpenAI Compatible

{ "provider": "openai", "openAiBaseUrl": "http://localhost:5000/v1", "openAiApiKey": "YOUR_LOCAL_KEY", "openAiModelId": "multillm" }

Same field names as Cline and Roo, since all three are VS Code extensions with the same provider settings component.

Neovim

Neovim

Where: In ~/.config/nvim/ through the opencode.nvim plugin, or the shared ~/.config/opencode/opencode.json

{ "$schema": "https://opencode.ai/config.json", "provider": { "multillm": { "npm": "@ai-sdk/openai-compatible", "name": "Multi LLM (local)", "options": { "baseURL": "http://localhost:5000/v1" }, "models": { "multillm": { "name": "multillm" } } } }, "model": "multillm/multillm" }

OpenCode needs the provider name and model name separated by a slash. That format is OpenCode's, not Multi LLM's.

Roo Code

Roo Code

Where: Roo icon › Settings › API Provider › OpenAI Compatible

{ "provider": "openai", "openAiBaseUrl": "http://localhost:5000/v1", "openAiApiKey": "YOUR_LOCAL_KEY", "openAiModelId": "multillm" }

Identical to Cline, since both are VS Code extensions from the same lineage. Roo also needs Use custom base URL switched on.

VS Code

Continue

Where: Settings gear icon › Chat › the model dropdown › Add Models › OpenAI Compatible

{ "models": [ { "name": "multillm", "provider": "openai", "model": "multillm", "contextLength": 128000, "baseUrl": "http://localhost:5000/v1", "apiKey": "YOUR_LOCAL_KEY" } ] }

Paste the JSON into the models array. If your setup already has entries, add Multi LLM as a second one instead of replacing the list.

Windsurf

Windsurf

Where: Windsurf icon › Settings › AI Providers › Add custom

{ "name": "multillm", "baseUrl": "http://localhost:5000/v1", "apiKey": "YOUR_LOCAL_KEY", "model": "multillm" }

Windsurf accepts a local URL; the provider must be set to OpenAI, not Anthropic.

Zed

Zed

Where: Cmd/Ctrl+comma › Language Models › OpenAI API Key

{ "language_models": { "openai": { "api_url": "http://localhost:5000/v1", "api_key": "YOUR_LOCAL_KEY" } }, "default_model": { "provider": "openai", "model": "multillm" } }

Zed needs the key in openai, not anthropic, even though Multi LLM translates to Anthropic under the hood.

CLI

Aider

Aider

Where: Environment variables in your shell or a .env file

export OPENAI_API_KEY=YOUR_LOCAL_KEY export OPENAI_API_BASE=http://localhost:5000/v1 export AIDER_MODEL=multillm

Aider treats everything as OpenAI. Note that it needs OPENAI_API_KEY set even though the value is your own local key, not an OpenAI one.

Claude Code

Claude Code

Where: Environment variables before starting the CLI

export ANTHROPIC_BASE_URL=http://localhost:5000 export ANTHROPIC_AUTH_TOKEN=YOUR_LOCAL_KEY export ANTHROPIC_MODEL=multillm

Claude Code speaks the Anthropic protocol, which Multi LLM translates. The base URL has no /v1 suffix here, unlike the OpenAI-compatible tools.

OpenCode

OpenCode

Where: In opencode.json in your project or ~/.config/opencode/

{ "$schema": "https://opencode.ai/config.json", "provider": { "multillm": { "npm": "@ai-sdk/openai-compatible", "name": "Multi LLM (local)", "options": { "baseURL": "http://localhost:5000/v1" }, "models": { "multillm": { "name": "multillm" } } } }, "model": "multillm/multillm" }

Neovim and OpenCode share one configuration file. Set it once in ~/.config/opencode/opencode.json and both pick it up.

Chat front end

AnythingLLM

AnythingLLM

Where: Settings › LLM Providers › OpenAI-like › Add

{ "apiBase": "http://localhost:5000/v1", "apiKey": "YOUR_LOCAL_KEY", "model": "multillm" }

AnythingLLM validates on save. Start the proxy before adding the provider, or the check fails.

Cherry Studio

Cherry Studio

Where: Settings › Model Services › Add custom service › OpenAI

{ "apiHost": "http://localhost:5000/v1", "apiKey": "YOUR_LOCAL_KEY", "models": ["multillm"] }

Cherry Studio names the base URL apiHost. It also needs a model added to the list before it appears in the picker.

LibreChat

LibreChat

Where: Settings › Providers › OpenAI › Add

{ "key": "YOUR_LOCAL_KEY", "baseURL": "http://localhost:5000/v1", "models": ["multillm"] }

LibreChat validates the connection before it accepts it. Start Multi LLM first, otherwise the test call fails.

LobeChat

LobeChat

Where: Settings › Language Model › OpenAI › Proxy URL

{ "apiKey": "YOUR_LOCAL_KEY", "apiBaseURL": "http://localhost:5000/v1", "models": ["multillm"] }

LobeChat stores the model list as an array, not a string. It is the only field where a comma-separated string fails silently.

Open WebUI

Open WebUI

Where: Admin panel › Settings › Connections › Add OpenAI-compatible connection

{ "name": "Multi LLM", "type": "openai", "config": { "URL": "http://localhost:5000/v1", "KEY": "YOUR_LOCAL_KEY", "MODELS": "multillm" } }

The connection type must be OpenAI. In the model list, add multillm by hand; Open WebUI does not discover models on its own.

TypingMind

TypingMind

Where: Settings › API › OpenAI Custom › Add

{ "name": "Multi LLM", "apiKey": "YOUR_LOCAL_KEY", "apiEndpoint": "http://localhost:5000/v1", "model": "multillm" }

TypingMind is web-based, so localhost means your own machine. From another device, use your LAN address instead.

Platform

Dify

Dify

Where: Settings › Model Provider › OpenAI-API-compatible › Add model

{ "model": "multillm", "api_base": "http://localhost:5000/v1", "api_key": "YOUR_LOCAL_KEY", "mode": "chat" }

Dify needs the mode set to chat. Leaving it on completion makes it send an old-style request the proxy answers with a 400.

Flowise

Flowise

Where: Chatflows › Tools › OpenAI › create a new OpenAI connection

{ "openAIApiKey": "YOUR_LOCAL_KEY", "openAIBasePath": "http://localhost:5000/v1", "modelName": "multillm" }

Flowise checks the key with a probe request on saving. If the proxy is not running yet, saving fails even though the settings are right.

Automation

n8n

n8n

Where: Credentials › New › OpenAiApi › Base URL override

{ "apiKey": "YOUR_LOCAL_KEY", "baseURL": "http://localhost:5000/v1", "model": "multillm" }

n8n runs in Docker, and there localhost is the n8n container. Use host.docker.internal instead, and enable Expose to LAN in Multi LLM.

Library

LangChain

LangChain

Where: In your Python or JavaScript code

from langchain_openai import ChatOpenAI llm = ChatOpenAI( base_url="http://localhost:5000/v1", api_key="YOUR_LOCAL_KEY", model="multillm", )

Any OpenAI client library works the same way. The three arguments are base URL, key and model — there is nothing Multi-LLM-specific in the code.

Common mistakes

It still reaches api.openai.com

The base URL field name does not match. Check the table above for your tool. A tool with an unrecognised key silently uses its default endpoint, so requests go out to the real provider and your local key is rejected there — which looks like a bad key rather than a wrong setting.

Connection refused

Multi LLM is not running, or the port differs. The API panel shows the exact URL to use. On Windows the firewall asks once for permission to open it; declining that leaves the proxy unreachable from other tools.

It works locally, not from a container

Inside Docker, localhost is the container itself. Use host.docker.internal and enable Expose to LAN. See Docker.

The tool does not list my models

Most tools do not discover models; they use what you type. Enter multillm by hand, or check GET /v1/models to see what the proxy actually exposes.

Streaming cuts off

Some tools assume every provider supports the same streaming events. If a response stops mid-sentence, turn streaming off in the tool and compare. The streaming page explains the differences.
