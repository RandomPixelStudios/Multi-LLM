Getting started

Install the app, create an account, confirm a request works, and connect your first tool.

Installation

Multi LLM ships as a ready-made package per platform. Nothing has to be compiled. Grab the file from GitHub Releases.

Windows

  1. Download multi-llm_<VERSION>_x64_en-US.msi or the setup.exe next to it.
  2. Run the installer. There is nothing to configure during setup.
  3. Start Multi LLM from the Start menu.
The .exe is the fallback

Use the NSIS .exe if the MSI does not fit your setup, for example on an older Windows or an unmanaged machine.

Linux

Three package formats ship. Pick whichever matches your distribution:

FileDistributionsInstall
.debDebian, Ubuntu, Mint, Pop!_OSsudo apt install ./multi-llm_<VERSION>_amd64.deb
.rpmFedora, RHEL, openSUSE, Rockysudo dnf install ./multi-llm-<VERSION>-1.x86_64.rpm
AppImageAny x86_64 distributionchmod +x *.AppImage && ./multi-llm_<VERSION>_amd64.AppImage

The AppImage runs from wherever you put it and installs nothing. The deb and rpm add an entry to your application menu and a tray icon for the running state.

Runtime libraries on Linux

The packaged builds need libwebkit2gtk-4.1 and libayatana-appindicator3-1. Debian 12+, Ubuntu 22.04+, Fedora 38+ and openSUSE Leap 15.4 ship both. The AppImage bundles what it needs.

macOS

  1. Download the aarch64 DMG for Apple Silicon (M1/M2/M3/M4) or x64 for Intel Macs.
  2. Open the DMG and drag Multi LLM into Applications.
  3. First launch: right-click the app, choose Open, then confirm. Gatekeeper only asks once.
Why the Open dialog appears

The DMG is not signed or notarised. Apple charges $99 a year for the signing certificate, which does not pay off for a private beta. The warning is expected and appears one time only.

Docker

The container image runs the same app in multi-user mode for a whole team. See Docker for the full setup, or jump straight to the commands:

git clone -b Docker https://github.com/RandomPixelStudios/Multi-LLM.git cd Multi-LLM/docker docker compose up --build -d docker compose ps # "healthy" once the port is bound

Then open http://localhost:5000 and create the first account, which becomes the admin.

First launch

Multi LLM keeps every API key on your own machine, so it starts with a single question: who is using it? Accounts are local. There is no sign-up, no e-mail address, no external login.

  1. Create a user

    Enter a username and a password of at least ten characters. That account is the first one and automatically becomes the admin.

    Add more accounts later from the user manager, or from the login screen. Each one gets its own providers, models, API key, usage history and personal port.

  2. Add a provider

    Open Providers and add a provider. The picker lists every supported service; you supply the base URL and the API key from that provider's own dashboard.

    Models are fetched from the provider once a key is present. Enable the ones you want to use.

  3. Watch the proxy start

    The status line at the top of the window turns green once the server is listening. The default port is 5000, changeable under API.

Where things are stored

Settings, provider configurations, API keys and usage figures live in your user profile directory. Nothing is sent anywhere. Export your configuration from Settings → Data before updating or moving machines.

Verify it works

Confirm the proxy answers before you wire up a tool. Open API → Client config snippets — the app shows a ready command for curl, Node, Go, PowerShell, Bash, Python, Java and jq.

With curl

Paste your key from API → API Keys:

curl http://localhost:5000/v1/models \ -H "Authorization: Bearer YOUR_LOCAL_KEY"

A JSON list of every enabled model comes back. If you get invalid_api_key, the key is wrong; if you get no models enabled, a provider exists but all its models are switched off.

With a completion request

curl http://localhost:5000/v1/chat/completions \ -H "Authorization: Bearer YOUR_LOCAL_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "multillm", "messages": [{"role": "user", "content": "Say hello in five words."}] }'

multillm is the built-in bundle. It picks a model for you using the routing strategy you picked, which is the easiest way to confirm the whole chain works.

What a healthy response looks like

  • HTTP 200 with a choices array.
  • The usage panel counts the request and its tokens.
  • Streaming works if you set "stream": true.

If a request fails, the provider card in Providers shows a red dot and the exact reason. See troubleshooting.

The three values

Any tool that speaks the OpenAI API needs three things. That is the entire integration — no plugin, no SDK change, no re-training of muscle memory.

Base URL
http://localhost:5000/v1
The port follows the API panel if you changed it. Some tools want the URL without /v1 — check the tool's own field label.
API key
Your local key from API → API Keys.
It authenticates you to your own proxy, not to a provider. Provider keys stay behind it and are never sent to the tool.
Model
Any enabled model name, or a virtual model.
Use multillm to let the proxy choose. Use an exact model id when you want one specific provider.
From a second machine

Enable Expose to LAN in the API panel, then use your machine's LAN address instead of localhost. The API tab shows the exact URL, and asks once for permission to open the firewall port on Windows.

Ready-made instructions for 21 editors, agents and chat front ends are on Connect a tool.

If something fails

These cover most first-run problems. The FAQ has more, and troubleshooting goes deeper.

The port is already in use

Another program holds 5000. Change the port in API → Port; every tool that points at localhost:5000 has to follow.

A provider shows no models

The key is wrong, the base URL does not match the provider's format, or the provider is unreachable from this machine. Use Test on the provider card — the result dialog names the reason, for example an HTTP 401 for a bad key.

A tool says "connection refused"

The proxy is not running. Check that the Multi LLM window shows a green status line, and that the tool's base URL points at the right port.

Nothing is counted in Usage

Only requests that pass through the proxy are counted. If you sent something directly to a provider, it does not appear here — and neither does the cost.

The tray icon is missing

On Linux the tray needs a StatusNotifier host. Without one the window still works, the icon just does not appear.
