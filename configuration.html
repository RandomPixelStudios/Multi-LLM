Settings

Configuration

Every setting in the app: what it changes, what it costs, and when to leave it alone.

Endpoint, port and key

The API panel holds the values every tool needs. Changes save automatically; there is no save button.

Base URL and port

The proxy listens on 5000 by default. Change the port and every tool that points at localhost:5000 has to follow. Pick something above 1024 to avoid privileged ports.

http://localhost:5000/v1

The API tab shows the full URL, ready to copy.

Enabled

Turns the HTTP server off without closing the window. Nothing is reachable while it is off — useful if you only want the UI open.

API key

Your local key, shown in the API tab. It authenticates a tool to your proxy. Double-click to generate a new one; the old key stops working immediately.

An extra key limits which models and how many requests per minute a given tool may use. Give a shared tool its own key rather than handing out the main one.

All models

Whether GET /v1/models lists models that are configured but switched off. Leave it on so tools can discover what exists; turn it off to hide models a tool should not reach.

Client config snippets

Opens ready-to-copy configuration for curl, Node, Go, PowerShell, Bash, Python, Java and jq, pre-filled with your URL, key and port. This is the fastest way to wire up something without a dedicated page.

Reaching it from other machines

By default the proxy only accepts connections from the same machine. That is the right setting for a laptop.

Expose to LAN

Listens on all interfaces, so other devices on the network can connect. The API tab then shows a URL with your machine's LAN address.

Only do this on a network you trust

Anyone on the network who has your local key can use your provider keys and spend your money. On Wi-Fi in a café, a hotel, or any shared network, leave this off and use a tunnel instead.

The Windows firewall prompt

The first time you switch it on, Windows asks for permission to open the port. Declining leaves the proxy unreachable from other machines, which looks like a network problem but is a local one.

From a container

Inside Docker, localhost is the container itself. Use host.docker.internal and enable Expose to LAN. See Docker and the network.

Providers and health

Adding a provider

Providers › Add provider opens a picker with every supported service. Pick one, paste the key from that provider's own dashboard, and the model list is fetched for you.

A local engine such as Ollama needs no key: give it the base URL (http://localhost:11434/v1) and leave the key empty.

Enable counts

Each card shows enabled / total models. A model only receives requests when it is enabled. Having four models configured and none enabled is a common cause of "no models" errors.

The health dot

Green means a probe succeeded recently, yellow means no recent probe, red means failing or the breaker is open. Click the dot's reset button to close a breaker by hand after fixing a problem.

Testing a provider

The test button on each card sends a real request. The result dialog names the cause when it fails: HTTP 401 for a bad key, a timeout for an unreachable host, a parse error for a wrong base URL.

Format

Most providers are OpenAI-compatible and need no change. Anthropic, Gemini and a few others have their own request shape — the provider preset sets this, and the picker fills it in.

Editing a provider id

Renaming a provider breaks the models bundled into virtual models that reference it. Use a new provider instead of renaming when something is already in use.

Virtual models

A virtual model is a named group of real models plus a strategy. Requesting the group asks the strategy which member to use.

The built-in bundle

multillm exists from the first start, contains every enabled model and uses weighted. Editing it changes what multillm means for every tool that uses it.

Creating your own

Virtual Models › Create opens a dialog: a name, a strategy, and a checkbox list of the models to include. The name is what tools will request.

A bundle can only pick from its members

Disabling a model removes it from every bundle that contains it. If a tool then reports that a model does not exist, check whether it was switched off rather than deleted.

Aliases

A model can carry an alias, shown in the models list. Useful when two providers use the same model name and a tool needs to target one specifically — aliases get an o- prefix.

Routing strategies

Set per virtual model. This is the strategy the bundle uses to pick.

StrategyPicksUse when
WeightedAt random, starred models four times as oftenDefault. Steer by starring.
Round robinEven rotation, no randomnessYou want every model used equally.
PriorityFirst healthy model in provider orderYou have a clear favourite.
LatencyLowest average response timeSpeed matters more than consistency.
FastestLatency weighted by current healthSpeed, but avoids a flaky provider.
StickyThe same model for a whole conversationMulti-turn work; reads better.
Sticky needs a conversation id

It keys on the conversation your tool sends. A tool that starts a fresh context every request gets no benefit — which is most tools by default. It becomes useful once your tool keeps history.

Change a strategy at any time; it takes effect on the next request. Existing conversations are unaffected unless the strategy is sticky.

Reliability and failover

Circuit breaker

After a set number of consecutive failures a provider is taken out of rotation for a cooldown period, then probed back in. This stops every single request from retrying a provider that is down.

When the breaker opens, the routing simply skips that provider. A request that would have failed takes a moment longer and succeeds instead.

Health history

Multi LLM keeps a short history of probe results per provider, shown on the card. It refreshes at most once a minute, so the numbers do not flicker while you watch.

Failover budget

How many alternative models a single request may try before giving up. Zero means no failover: the first error reaches you.

A budget exists so a request cannot loop forever when every candidate is broken. Two is usually enough: your favourite plus one fallback.

Daily budget

Set a spend limit and the usage panel warns at 80 percent. It is a warning, not a cut-off — requests keep working.

Token compression

Removes filler from your prompt before it leaves the machine. Providers bill by token, and long instructions carry a lot of words that change nothing.

Strength

LevelEffect
1–3Mild. Only obvious filler: "please", "I would like to".
4–6Noticeable savings on chatty prompts.
7–10Aggressive. Test before relying on it.

What is never touched

  • Code blocks, including fenced sections
  • JSON, in any form
  • Anything that looks like a literal or an identifier
  • The system prompt's role markers

These are exactly the parts where a "harmless" rewrite changes meaning. The compressor skips them rather than risking your code.

Compression is for prose

It helps when you paste long explanations and hurts nothing. It cannot make a big codebase smaller — code is excluded on purpose.

Response cache

Identical non-streaming requests are answered from a local store instead of being forwarded. Same prompt, same model, same parameters means the same answer anyway.

What is cached
Non-streaming chat and completion requests. Streaming is never cached — replaying a recorded stream looks like a hang.
Time to live
How long an entry stays valid. Short is safer: models change behind the same name.
Max entries
Upper bound on stored responses, oldest evicted first. Keeps memory use predictable.
Good for repetition, wrong for freshness

Use it for fixed instructions you send repeatedly. Do not use it for anything where a stale answer is wrong — a lookup, a current price, a question about a file you just changed.

Startup and updates

Start with Windows

Launches the proxy when you sign in, so tools work before you open the window. Windows only; on Linux use your desktop session's autostart.

Check for updates automatically

On start-up, the app fetches a small version file. That request reaches GitHub, so your IP address is visible to them. Switch it off to make no outbound request at all; the manual check stays available.

Check for updates

Checks once, on demand, and shows the result. Nothing is downloaded automatically — if a newer version exists, you get a link.

Update server

Where the version file is fetched from. Empty means the official one. Change it if you run your own fork with its own release cycle.

Updates are never automatic

Multi LLM tells you a new version exists and stops there. You download and install it yourself, which keeps a beta from changing under you mid-session.

Data, export and import

Export config

Writes your providers, models and settings to a JSON file. A checkbox decides whether API keys go in.

Keys are secrets

A config exported with keys is a plain text file containing your provider credentials. Export without them unless the destination is somewhere you fully control.

Import config

Merges a previously exported file. Existing entries with the same name are updated rather than duplicated, so importing an older file can roll your configuration back.

Export usage

Your token history as JSON, for your own accounting. Contains no keys.

Where files live

Everything is in your user profile directory: settings, keys, usage and accounts, one folder per user. See backup for copying it.

Legal texts

Imprint, privacy policy and terms are available in the app under Settings › About & legal, with three tabs to switch between them.

The same texts are online on the legal page. They cover what the app stores, what leaves your machine, and where the liability boundaries are.

Read the compatibility clause before deploying

Section 5 limits liability for compatibility and environment failures — OS updates, missing libraries, firewalls, occupied ports. Worth knowing before you run this on someone else's machine.
